# 测试规则（compositor 版）

改编自 gpui-component 的 `.agents/COMPONENT_TEST_RULES.md`，按本项目的移植
验收模式改写。上游原文以 Apache-2.0 授权，本改编稿随本项目以 MIT 发布。

## 0. 验收标准：移植的 XCTest

本项目的验收标准是**从原版 XCTest 移植的测试**（见 README"1:1 restoration,
verified by tests ported from the original XCTest suite"）。

- 移植一个原版测试时，保持与原用例**可对照的命名与结构**（如
  `testLevelsApplyBlackPoint` → `levels_apply_black_point`），便于逐条核对
  覆盖进度。
- **不许为了让移植测试通过而修改断言值或放宽容差。** 失败时先怀疑移植错了：
  对照 `Compositor/` 原版源码（Swift + C 内核）逐行核查。
- "kernel-exact"（与 C 内核逐位一致）断言是本项目最有价值的资产，永远不因
  "写法更现代"而改动其期望值。

## 1. Simplicity First

- 避免过量简单测试；聚焦复杂逻辑与核心功能。
- 每个移植决定都优先服务"与原版对齐"这个目标，而不是服务测试数量。

## 2. 构造覆盖测试

新增（非移植的）模块时，每个有配置面的类型应有一个覆盖完整构造链的测试，
用链式调用展示完整 API 用法，并断言关键属性；相关的零散配置断言合并进这一
个测试，不逐属性单开。

## 3. 复杂逻辑测试

测试条件分支、状态转移与边界情况。本项目典型对象：undo 守卫与事务边界、
选区布尔/羽化的退化几何、blend 全模式表、transform 的吸附与拖拽分支、
project manifest 的版本语义与校验上限。

## 4. 合并相关断言

一个行为族一个测试函数，不按属性/尺寸/变体拆成多个测试。

## 反模式清单

❌ 禁止：

1. 逐属性单开测试（`test_button_disabled` / `test_button_selected` 各一个）
   ——合并进构造覆盖测试。
2. 逐尺寸/逐变体单开测试。
3. 测试显而易见的功能（getter 直进直出）。
4. 过度碎片化。
5. 修改移植测试的断言值来让它通过（见第 0 节）。
6. 为纯视觉尺寸写断言测试；测试行为、交互、数据流与有意义的回归。

## 测试数量指引

| 模块类型 | 建议测试数 | 说明 |
| --- | --- | --- |
| 简单模块 | 1–2 | 构造覆盖 + 复杂逻辑（如有） |
| 中等模块 | 2–3 | 构造覆盖 + 逻辑 + 辅助方法 |
| 复杂模块 | 3–5 | 按实际复杂度；移植测试不计入此列 |

## GPUI 测试的使用

### 用 `#[gpui::test]` 当：

- 测试 app crate 的 UI 行为（窗口、面板、sheet、事件处理）；
- 测试依赖窗口/GPUI 上下文的交互。

### 用普通 `#[test]` 当：

- core crate 的纯逻辑（本项目绝大多数测试：几何、像素内核、调整表、格式
  解析）——不涉及渲染就不要拉起 GPUI 上下文。

**Goal**: 用最少的测试覆盖最关键的功能，同时与原版行为逐位对齐。
